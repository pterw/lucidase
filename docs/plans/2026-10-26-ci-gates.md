# CI, a PR Template and Scoped Pre-commit Checks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the five gates of `CLAUDE.md` ("Gates (all five, in order)") on every pull request and on every push to `main`, on Linux; give the repository a PR template; and run only the checks a commit touches before it is made. Today there is none of the three (`CLAUDE.md:12`: "There is no CI."; no `.github/`, no `.pre-commit-config.yaml`).

**Architecture:** One workflow, `.github/workflows/gates.yml`, one job `gates`, five named steps that are exactly the five gate commands. One pinned dependency manifest, `requirements-ci.txt`, holds what the gates import. `.pre-commit-config.yaml` holds local hooks scoped with `files:`; the one decision pre-commit cannot express (which unit tests a staged file affects) lives in one tested script, `tools/precommit_scope.py`. The PR template is plain Markdown.

**Tech Stack:** GitHub Actions; Python 3.13; Node 24; Playwright Chromium; Tailwind standalone CLI v3.4.17; `pre-commit` 4.x (developer machine only). The local launcher (Task G) uses the Python standard library only.

Branch `infra/ci-gates`, cut from `main` 34acbe2, merged before PR #7 (the design-gap branch).

## Global Constraints

- CI runs exactly the five gate commands of `CLAUDE.md:63-70`, in that order, character for character. A step never adds a flag the local gate lacks, so a green run means the same thing in both places.
- **A silent green is worse than a red.** Every skip path fails loudly: a missing Tailwind CLI is an error exit in `tools/check_vendored_css.py:25-36`, and the unit step runs after `TAILWIND_CLI` is exported so `tests/test_check_vendored_css.py:91-92` (`pytest.skip("Tailwind CLI not installed")`) cannot skip in CI.
- Tests assert the intended outcome, not that code ran. No test pins wording or file layout. Good docstrings: the one script has a module docstring and one per public function.
- No secret, no `.env`, no token beyond the default read-only `GITHUB_TOKEN`. The only network use is CI's own pinned installs (pip, the Playwright browser, the Tailwind binary); the tests stay offline (`CLAUDE.md`, owner rulings).
- No formatter or linter is added: `ruff check .` reports 309 errors on `main` today, so a linter hook would fail on files this PR does not touch.
- Third-party actions (`actions/checkout`, `actions/setup-python`, `actions/setup-node`, `actions/cache`) are pinned by major version tag (for example `@v4`), not by commit SHA; they are first-party GitHub actions and the token is read-only.
- Docs describe only shipped behaviour. Task E runs after A-D and G have landed.
- Commits: `type(scope): summary`, one concern each, a body for a developer reading `git log`. Never amend, rebase, reset or `--no-verify`. No attribution line. Stage files by name.

### Task C1: The scoped-test helper

Wave: 2 · Touches: `tools/precommit_scope.py`, `tests/test_precommit_scope.py` · After: B · Mode: code

**Interfaces:** `select_tests` and `main` as written in "Frozen interfaces".

**Behaviour**
- `select_tests(root, staged)` returns the unit test files to run. Excluded: anything under `tests/e2e/`. Rules, in one pass over the staged paths:
  - a staged `tests/test_*.py` selects itself;
  - any other staged `*.py` selects every `tests/test_*.py` whose text imports it (`import <stem>`, `from <stem> import`, `from tools.<stem> import`, `from tools import <stem>`) or names its file (`<stem>.py`);
  - any other staged file selects every `tests/test_*.py` whose text contains its file name with extension (for example `app.js`).
- The result is sorted and has no duplicates; a staged path that does not exist is ignored (it selects nothing and does not crash).
- The import rules are textual: a multi-line `from tools import (a, b)` is not matched, and a module imported only through another module (for example `bio_engine.py` reached by a test via `gui`) selects nothing. Both are Known gaps.
- `main(argv, *, runner, root)` calls `select_tests(root, argv)`; with an empty selection it prints one line saying nothing was selected and returns 0 **without calling `runner`** (a bare `pytest` would run the whole suite); otherwise it calls `runner(["python", "-m", "pytest", "-q", "-p", "no:cacheprovider", *selected files])` (the default `runner` is `subprocess.call`) and returns the value `runner` returns.
- Module docstring states the rules and why an empty selection never reaches pytest; each public function has a docstring.

**Acceptance checks** (tests in `tests/test_precommit_scope.py`, against a temporary tree they build)
1. A staged unit test file selects exactly that file.
2. A staged `tools/foo.py` selects the test that has `from tools.foo import x` and not one that only mentions `foobar`.
3. A staged `web/src/app.js` selects a test whose text contains `app.js`.
4. A staged file under `tests/e2e/` and a staged `docs/x.md` select nothing, and `main(..., runner=fake, root=tmp)` returns 0 with the fake runner never called.
5. A selection that includes a failing test file makes `main` return non-zero when the runner is `subprocess.call` with `cwd` set to the temporary tree (a real failing test file in it, so a swallowed exit code is caught).
6. A staged path that does not exist selects nothing and `select_tests` does not raise.
7. RED/GREEN, one named mutation per check: with `select_tests` replaced by `return []`, checks 1, 2, 3 and 5 fail; check 4 has its own red, a `main` that calls the runner on an empty selection; check 6 fails with a `select_tests` that raises on a missing path (or selects everything).

**Behaviour**

Where the cause is the workflow or the environment, the commit changes only that and cites the failing line.
- A fix never weakens a test, adds a skip or relaxes a gate command.
- A red e2e step whose only error is a `net::ERR_ADDRESS_IN_USE` or `net::ERR_NO_BUFFER_SPACE` line is re-run once by hand before it counts as a cause (Known gaps 9).

## Known gaps

Accepted; nobody may rely on more than this list.
1. Windows-green does not prove Linux-green. Line endings, path separators, fonts and timing can differ; Task F exists for that, and it is the reason the PR is not marked ready before a green run.
2. e2e timing on a shared runner: the 20 s waits (`tests/e2e/conftest.py:24`) may need a longer ceiling, or a retry-free rerun by hand, after the first run.
3. Pre-commit runs only the unit tests it can connect to a staged file by name or import; a behaviour change in a file no test names runs no test locally. CI and the pre-PR full run are the backstop.
4. `pre-commit` hooks are installed by the developer, not by the repository; `git commit --no-verify` is forbidden by the rules but not prevented.
5. Branch protection is not set by this plan; until the owner sets it, a red run does not block a merge.
6. The pinned Tailwind sha256, its README line and the two cache keys are written once; a Tailwind or Playwright upgrade changes them in the same commit.
7. The scoped helper does not select `tests/test_zero_knowledge_privacy.py` for a change to a `web/src/**/*.js` file the test does not name, although the test scans every such file. CI and the pre-PR full run are the backstop.
8. The scoped helper's import matching is textual: a multi-line `from tools import (...)` is missed, and a module reached only through another module's import selects nothing.
9. e2e serves on an ephemeral port (`tests/e2e/conftest.py:48`), and the local machine has shown `net::ERR_ADDRESS_IN_USE` and `net::ERR_NO_BUFFER_SPACE` console errors when several Chromium suites run at once. A red e2e step whose only error is such a line is re-run once before Task F treats it as a cause.
10. Typekit is stubbed (`tests/e2e/conftest.py:67`), so layout tests measure fallback fonts on both platforms; the fallback font differs between Windows and the Linux runner.
11. `core.autocrlf=true` locally versus LF on the Linux checkout, for every file outside the `-text` fixtures (`.gitattributes:1`); a test that reads a file's bytes may differ.
12. `biotools_orchestrator.py:418` reads an optional `~/.env`; it is absent on the runner, and the tests pass without it (offline).
